# TF 本地音乐

本模块为 AC791N 1.2.14 的 GC9307/HYN Product UI 提供板载 TF 音乐播放。
插卡或带卡开机只扫描；必须点击歌曲才播放。界面分为歌曲列表和当前播放页，
布局参考 LVGL 自带 music demo 的分区和主控层级，使用本项目控件与配色；
唱片图形是通用占位图案，不是从歌曲读取的封面，不展示模拟频谱。

## 使用与硬件

- 使用 FAT32 卡，将 MP3/WAV 放在根目录或其子目录。SDK 的 `storage/sd0/C/` 是挂载分区路径，用户不需要创建名为 C 的文件夹。
- 最多载入前 200 首，按 SDK 文件号顺序排列，每页 10 首。200 是产品曲库上限，并不限制 SDK 扫描内部内存；递归深度参数为 9。
- 点击歌曲打开播放页；列表键返回曲库，声音键打开现有音量设置。进度条不可拖动。控制中心使用相同的播放状态。
- 顺序播放到末尾回到第一首；上一首/下一首在首尾循环。离页和熄屏不停止后台服务。
- 对话、闹钟和维护操作结束后不自动恢复音乐。内存断点只用于本次介质版本；切歌、重扫、拔卡使旧断点失效。
- 已扫描的歌曲列表可在对话或闹钟占用声音时浏览，选曲播放仍受音频交接约束。维护、启动、音量事务、换卡清理及停止未完成时，分页等待安全条件恢复；被占用打断的分页保留请求，恢复后继续读取。首次扫描与重扫仍等待音频占用释放。
- 文件读取、格式或断点错误通过界面状态反馈。不能把 SDK STOP 失败当作已经暂停；资源可能仍被使用，后续音频接管会被拒绝。

| 信号 | GC9307/HYN 演示板连接 |
| --- | --- |
| SD0-A CMD | PB6 |
| SD0-A CLK | PB7，20 MHz |
| SD0-A DAT0 | PB5，单线 |
| SDGAT | PB8，通过 SDK `sd_set_power` 回调 |
| 独立卡检测 | 板上 PB4，当前采用命令检测 |

四线模式会影响 PB3 串口和 PB2 功放 MUTE。本实现不启用四线；EMI 的 PB8 背光也不启用 SDGAT 配置。
SDK 解码器、文件系统和 SD 驱动仍来自原工程，没有新增外部硬件解码器。

## 所有权与接口

- `platform/storage/d_storage` 保存 SD 介质版本，SDK 设备事件先更新它再发布通知。只读快照不挂载，`d_storage_sd_prepare` 才调用 SDK 已有的带锁就绪/挂载路径；不格式化。
- `music_service` 的单一 `local_music` 工作任务执行扫描、分页、播放、停止和音量操作。命令返回接受结果，`completed_id/command_result` 确认完成。唤醒队列满时，保留的意图由任务定期处理。
- `music_backend_wl82` 是本服务内部 SDK 边界；文件、扫描句柄、解码器及 SDK 断点指针不会进入公开快照。每次解码注册独立代次，STOP 成功后清理回调、关闭 server，再关闭文件。
- `music_config_t` 在启动时装配格式、上限、循环方式和产品准入回调。应用决定优先级；服务不包含 Qwen 或 LVGL 头文件。
- `product_ui_media_runtime` 属于产品应用层，在页面创建前绑定音乐、Qwen、提醒音、音量和关机接口。单一媒体音量后端由它装配，Qwen 关闭的配置也使用相同入口。
- 初始音量同步完成后才允许扫卡，避免慢卡阻塞唯一音量后端注册。音乐等待提醒音停止时，不允许音量任务反向等待音乐任务；超时音量请求不作为已确认设置，迟到的 SDK 写入需要停止后再恢复。
- `product_ui_music_page` 仅持有一个显示窗口。音乐曲库与相册队列分离；页面销毁不销毁服务。歌曲定位使用曲库版本及文件编号，不使用截断后的显示名称。
- Qwen 启动请求立即提交音乐让路意图，后台再确认停止；真实音频准备再次核对准入。闹钟优先于语音，语音优先于音乐。小乐待机监听不单独阻止音乐。
- OTA 与关机先关闭准入，再让所有者自行收尾；取消时仅恢复已释放的资源。部分交接失败和迟到释放保留待处理状态，不清除其他所有者的标记。

占用接口使用单个原因位和非零单调代次。音乐服务原子检查代次、资源空闲与释放，
旧 begin/release 不能覆盖新持有者；产品层的 Qwen 占用、开始结果和释放标记也随同一代次更新。
关机和 OTA 是两个维护客户端。取消意图会保留到音乐停止完成，旧取消不会解除新维护；
OTA 在尚未取得音乐占用前失败，也不会等待其他正在播放的持有者。

媒体音量先更新各后端，再由统一音量服务确认提交。部分失败时恢复此前确认的音量；
新播放同时检查统一音量是否仍在提交，避免读取中间值。回滚无法确认时保留故障占用，
停止音乐并请求停止语音；完整重设音量成功、统一服务确认且相关音频已停止后才解除。
因此故障恢复后需要手动继续音乐；音量无法重设或停止仍失败时，不允许带着不确定状态重新播放。

同代次的重复语音请求加入已接受的准入事务，通过 poll 等待完成；迟到的旧请求不能取消
或覆盖新会话。音乐工作任务若创建失败，产品层使用现有 sys_timer 任务中的一个 100 ms
定时回调继续处理恢复，回调不等待服务、不操作解码器，也不依赖页面。该回调只在此降级
情况下创建；音量后端注册失败会撤销本次创建的定时器，成功后随产品运行至重启。

不增加 VM 索引，不写 TF 索引，不使用旧音乐服务的独立音量存储。
断点是唯一按 SDK 合同接收并释放的动态载荷；曲库元数据使用固定页缓存。
扫描取消回调只检查介质版本和设备在线位，不在 SDK 文件系统回调里再次查询挂载表。
